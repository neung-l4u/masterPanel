## แต่ละหัวข้อหมายถึงอะไร

เรียงตามลำดับความด่วน สองหัวข้อแรกคือสิ่งที่ต้องโทรวันนี้

| หัวข้อ | หมายความว่า | ใครดู |
|---|---|---|
| 🚨 **ต้องโทรวันนี้** | นาทีหมดแล้ว หรือเหลือ ≤ 30 นาที — สายเดียวยาวก็หมด | ทีมขาย |
| ⏳ **นาทีจะหมดก่อนรอบรีเฟรช** | ยังไม่เหลือน้อย แต่คิดจากอัตราใช้จริงแล้วไม่พอถึงรอบใหม่ | ทีมขาย |
| 💰 **โอกาสอัพเซลล์** | นาที < 70 และรีเฟรชอีก ≤ 15 วัน | ทีมขาย |
| 📉 **ไลฟ์แล้วแต่แทบไม่ได้ใช้** | ไลฟ์มา ≥ 10 วัน แต่ใช้ไป < 15% ของโควตา | PO ของร้าน |
| 📉 **เคยใช้แล้วหายไป** | รอบล่าสุดใช้ < 30% ของค่าเฉลี่ย 3 รอบก่อน | PO ของร้าน |
| 🚧 **ทำไมยังไม่ไลฟ์** | ร้านที่ setup ค้าง เรียงตามจำนวนวันที่ค้างนานสุด | PO ของร้าน |
| ❌ **แจ้งยกเลิก** | ร้านสถานะ Waiting to cancel + เหตุผล | PO ของร้าน |
| ⚠️ **ข้อมูลไม่ครบ** | ร้านที่ระบบเช็กให้ไม่ได้ พร้อมบอกวิธีแก้ | คนดูแลบอร์ด |

ร้านที่ **แจ้งยกเลิกแล้วจะไม่ขึ้นในสองหัวข้อแรก** และไม่ขึ้นในอัพเซลล์
เพราะโทรไปขายนาทีเพิ่มกับร้านที่บอกเลิกแล้วคงไม่เหมาะ

- [ ] **Chiva Raks Holistic Spa and Wellness Centre** — ชื่อในบอร์ดไม่ตรงกับใน gcal

      **นาทีของร้านนี้ไม่ขึ้นในรายงานเลย**
      → ใส่ Google Calendar ID ในบอร์ด (ดีกว่าแก้ชื่อ เพราะกันปัญหานี้ถาวร)

- [ ] **SUPERTHAI MASSAGE** — มีใน gcal แต่ไม่มี item ในบอร์ด
      → ถ้าเป็นลูกค้าจริงให้เพิ่มในบอร์ด ถ้าเป็นร้านเทสต์หรือเลิกใช้แล้ว ข้ามได้

อีก 25 รายการในหัวข้อเดียวกันเป็นร้านที่ยกเลิกไปแล้ว ไม่ต้องทำอะไร
— ระบบแยกไว้ให้แล้ว ไม่ปนกับของจริง

## กรอก 2 ช่องนี้ รายงานจะแม่นขึ้นมาก

ระบบจับคู่ร้านระหว่าง Monday กับ gcal ด้วย **Google Calendar ID → อีเมล → ชื่อร้าน** ตามลำดับ

| ช่องในบอร์ด | ถ้าว่างจะเกิดอะไร |
|---|---|
| **Google Calendar ID** | ต้องพึ่งชื่อร้านแทน ซึ่งสะกดต่างกันได้ง่าย — ใส่ไว้แล้วไม่มีปัญหาเรื่องชื่ออีกเลย |
| **Live Date** | คำนวณไม่ได้ว่าอยู่กับเรามานานแค่ไหน และ **กฎร้านไม่ได้ใช้งานจะไม่ทำงานเลย** |
| **Reason For Cancel** | เวลาวิเคราะห์ churn ย้อนหลัง จะไม่รู้เหตุผลที่ลูกค้าเลิก |

ตอนนี้ร้าน LIVE ทุกร้าน **ยังไม่มี Live Date ในบอร์ด** ระบบเลยใช้วันสมัครจาก gcal แทนไปก่อน
และระบุไว้ในรายงานว่าใช้แหล่งไหน — ถ้ากรอก Live Date จริงเมื่อไหร่ ระบบจะสลับมาใช้ค่านั้นทันที
ไม่ต้องแจ้งใคร

## ยังไม่มีในรายงาน (ตั้งใจ)

| หัวข้อ | เหตุผล |
|---|---|
| รายได้ / ยอดเงิน | ข้อมูลพร้อมแล้ว แต่กันไว้รอบหน้าเพื่อให้รอบแรกได้ใช้งานก่อน |
| คุณภาพสายรายร้าน (จอง/โอน/วางสาย) | ต้องตรวจค่าที่ระบบบันทึกจริงก่อน ยังไม่กล้าเดา |
| ร้านที่ขาดการติดต่อ (Respond.io) | ยังไม่ได้เชื่อมระบบ |
| สถานะ Stripe / ค้างชำระ | ยังไม่มีการ sync สถานะมาเก็บไว้ |
| สัญญาใกล้หมดอายุ | ยังไม่มีที่เก็บวันหมดสัญญาในระบบไหนเลย |
| @mention แล้วเด้งเตือนจริง | ตอนนี้เป็นข้อความธรรมดา ต้อง map ชื่อ Monday กับ Chat user ID ก่อน |
